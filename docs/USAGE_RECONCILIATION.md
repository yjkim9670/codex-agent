# Usage 날짜 보관 및 계정/로컬 차이 추적

코드 수정 범위는 `dev_workspace/codex_workbench/`입니다. 모든 Workbench는 기존 구성으로 유지합니다.

## 날짜 보관

- 한국시간 오늘을 포함한 최근 90개 날짜를 보관합니다. 예: 2026-10-01 기준 2026-07-04 00:00 이후입니다.
- 사용률, 계정 누적 토큰, 프로젝트별 누적 토큰에 적용됩니다. 샘플이 2,160건을 넘어도 기간 안이면 보관합니다.
- 첫날 증가량 계산을 위해 기간 직전 누적 토큰 샘플을 계정 및 프로젝트별로 하나씩 남깁니다.
- 자동 조회 진단 로그의 500건 제한과 keepalive 상태 이력의 50건 제한도 날짜 보관으로 변경했습니다.
- 조회, 저장, 원본 가져오기, 로컬→공용 병합에 같은 정책을 적용합니다.
- 이미 삭제된 샘플을 복구하는 기능은 포함하지 않습니다. 일별 토큰 원장과 사용 이벤트는 기존 방식으로 유지합니다.

## 차이 추적

각 계정의 `codex_usage_reconciliation.json`에 성공한 계정 조회 시점마다 비교 결과를 저장합니다. 계정 공용 경로와 파일 잠금을 사용하며 90일간 보관합니다.

- 최근 30일 날짜별 계정 토큰, 로컬 토큰, 차이(`계정 - 로컬`), 로컬 기록 존재 여부
- 계정 일별 미제공 여부 및 오늘의 진행 중 상태
- 계정/로컬 누적값과 직전 조회 대비 각각의 증가량, 차이 증가량, 누적값 감소 여부
- API 관측 시각, 비교 시각, 로컬 원장 갱신 시각, 조회 오류
- 같은 조회 시각을 다시 처리해도 처음 기록한 로컬 누적값을 유지합니다.

계정 API는 계정 전체를 집계하고, 로컬 원장은 Workbench가 기록한 작업을 집계합니다. API 일별 날짜의 시간대는 확인되지 않았으므로 API 날짜 문자열과 KST 날짜를 비교한 결과입니다. 차이는 누락량 확정치가 아닙니다. API 일별 데이터가 없는 날짜는 0으로 가정하지 않습니다.

`/api/codex/usage/history` 등의 응답에서 `usage.usage_reconciliation`으로 현재 비교, `latest_observation`, `trend`를 조회할 수 있습니다. 현재 비교는 최신 로컬 원장 기준이며, 저장된 관측값은 당시 값입니다. 화면에 별도의 비교 카드를 추가하지 않았습니다.

## 실행 및 적용

읽기 전용 보고서 생성:

```sh
python3.14 scripts/reconcile_usage_history.py \
  --account-root /Users/dinya/.codex-workbench/accounts/yangjina-kim \
  --days 30 --output tmp/usage-reconciliation.json
```

`--record`를 추가하면 캐시된 관측값을 공용 추적 파일에 기록합니다. API 조회나 서버 재시작은 실행하지 않습니다.

Git 동기화 후 사용자가 모든 실행 중인 Workbench 서버를 재시작해야 날짜 보관과 자동 차이 추적이 적용됩니다. 기존 코드가 실행 중인 서버는 계속 2,160건/500건 제한을 적용하므로 공용 기록을 다시 줄일 수 있습니다. 이번 작업에서 서버 재시작이나 기존 사용량 원장 변경은 수행하지 않았습니다.

## 검증

사용량/이력/가져오기 관련 테스트 42개 통과. 날짜 경계, 2,500개 고밀도 샘플, 프로젝트별 기준 샘플, 600개 진단 기록 보관, 미제공 날짜, 음수 차이, 관측 중복 방지, 조회 간 차이 증감을 검증했습니다.

전체 스트림 테스트에서 기존 Python 실행 환경 검사와 subprocess 모의 구현 충돌로 20개가 실패합니다. 동일한 20개는 수정 전 HEAD 코드를 메모리에 로드한 검사에서도 실패했습니다. 최종 전체 검사 결과는 200개 통과, 기존 실패 20개입니다.
