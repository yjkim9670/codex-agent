# 에이전트 공통 대화 문맥

Codex·Claude·OpenCode 실행은 같은 문맥 구성기를 사용한다. 모델이나 CLI 이름을 공통 프롬프트의 역할로 고정하지 않는다. 특정 백엔드의 설치·버전·명령 옵션을 설명하는 문구는 실제 백엔드 이름을 사용한다.

## 선택 순서

1. 이번 사용자 요청을 공백과 줄바꿈을 포함해 그대로 보존한다. 역할 경계, 작업 경로 제한, 실행 환경, 응답 지침도 유지한다.
2. 과거 발화에서 지시·제약·취소·계획·미완료 관련 문장을 규칙으로 추출한다. 사용자 원문을 assistant 제안보다 우선한다. 각 항목에는 원문 메시지 ID/번호, 발화자, 종류, 검토 상태가 있다.
3. 직전 사용자 요청과 답변을 같은 묶음으로 선택한다. 긴 발화는 시작과 끝을 함께 남기고 중간 생략을 명시한다.
4. 같은 세션에서 이번 요청과 어휘·파일명·오류명이 겹치는 과거 대화 묶음을 찾는다. 짧은 후속 요청은 직전 묶음의 어휘도 검색에 이용한다. 나머지 공간은 최근 묶음으로 채운다.
5. 실제 조립 결과와 선택 기록의 크기를 다시 확인해 과거 묶음·기억을 줄인다. 이번 요청과 필수 지침만으로 설정을 넘으면 자르지 않고 초과를 기록한다.

`CODEX_CONTEXT_MAX_CHARS`는 호환성을 위해 유지한 **문자 기준의 과거 문맥 예산**이다. 모델별 토큰 한도 계산이나 자동 의미 요약은 수행하지 않는다. 최신 요청이 백엔드의 실제 입력 한도보다 큰 경우 CLI가 거절할 수 있다.

## 지시와 제안의 구분

추출 기억은 의미를 확정한 작업 상태표가 아니라 출처가 있는 원문이다. 사용자 항목은 `requires_chronological_review`, assistant 항목은 `unconfirmed_by_user`로 저장한다. 최신 사용자 요청과 후속 정정·취소를 우선하며, 짧은 동의가 관련 없는 모든 제안을 승인한 것으로 처리되지 않도록 공통 지침을 넣는다. 규칙에 걸리지 않는 제약은 추출 기억에서 빠질 수 있고, 과거 문맥 예산이 작으면 일부 기억도 생략된다. 모든 원문은 기존 세션에 그대로 남는다. 전체 추출 후보는 실행 시작 시 세션의 `context_memory`에 별도 스냅샷으로 저장하고, 실제 전달한 부분만 응답의 `context_selection.memory`에 저장한다. 다음 실행에서 수정·삭제된 원문으로 다시 추출하며, 이 스냅샷 자체를 승인된 지침으로 재사용하지 않는다.

과거 첨부의 이름·경로·MIME 정보를 전달한다. 첨부 내용 자체의 자동 읽기, 과거 이미지의 자동 재첨부는 하지 않는다. 에이전트는 실제 파일이 남아 있는지 확인해야 한다. 다른 세션·사용자·작업 공간의 기록을 검색하지 않는다.

## 확인 가능한 기록

`Context Selection Record`를 프롬프트에 덧붙이고 assistant 메시지의 `context_selection`에 저장한다. 대기열 실행·부분 응답·완료·사용자 중지에도 같은 기록을 유지한다. 기존 세션 조회 API와 세션 JSON에서 확인할 수 있다.

기록에는 선택한 메시지 ID/번호와 이유, 축약 여부, 첨부 수, 생략 번호 구간과 개수, 전달한 추출 기억과 생략 수, 적용 섹션, 문자 예산과 초과 여부, 조립 문맥 SHA-256이 있다. 저장할 때에는 추가 지식/계획 지침을 포함한 제출 단계 프롬프트의 길이와 SHA-256도 기록한다. 실행 직전 첨부·경로 등의 백엔드 부가 문맥은 이 제출 단계 해시의 대상이 아니다. 별도 전역 대화 복사본이나 UI는 만들지 않는다.
