가성비 결론

  1. Luna는 Sol보다 4.1점 낮은 84.7%를 20% 비용 지수로 냅니다. 범위가 명확한 구현·수정의 1순위입니다.
  2. Terra는 Sol과 1.4점 차이인데 50% 비용 지수입니다. Luna가 막히는 일반적인 터미널 작업의 최적 승급입니다.
  3. Sol은 최고 성공률이 성공 자체의 가치보다 중요한 대형 디버깅·설계 작업에 씁니다. 5.5는 같은 비용 지수에서 2.1 기준 성능이 낮아 기본 선택의 우선순위가 낮습니다.
  4. 5.4-mini는 5.4 계열 안에서 높은 효율을 보이지만, 절대 성공률은 60.0%이므로 작은 패치·탐색·subagent에 맞습니다.
가성비 1위 ≠ 어려운 작업의 성공률 1위
비교 주의: 5.6/5.5는 Terminal-Bench 2.1, 5.4/mini는 Terminal-Bench 2.0 공개 점수입니다. 벤치 버전·harness가 달라 두 평가군의 점수와 가성비 지수를 서로 순위화하지 않았습니다. 5.4 계열은 xhigh 조건이 명시됐지만, 5.6/5.5 표는 effort를 명시하지 않습니다. 따라서 가성비는 공개 성공률에 이 문서의 xhigh 사용량 가정을 결합한 운영용 proxy이며, high와 xhigh의 실제 성능 차이를 추정한 값이 아닙니다.

가장 실용적인 기본값

Luna · high

Terminal-Bench 2.1에서 84.7%를 기록하면서 기준의 약 14% 사용량입니다. 범위가 명확한 구현, 반복 수정, 짧은 분석의 기본값입니다.

막히면 Terra · high(36%)로 올리면, 2.1 기준 성공률 87.4%까지 빠르게 회복합니다.

xhigh를 쓸 때

큰 설계 결정, 원인 불명 디버깅, 광범위한 리팩터처럼 한 번의 성공이 반복 시도보다 싼 경우에만 선택합니다.

같은 모델이라도 high보다 더 오래 생각하게 하므로 응답 시간도 함께 늘 수 있습니다.

우선 확인할 것

모델 선택보다 브라우저를 여러 번 열거나, 같은 테스트를 재실행하거나, 긴 컨텍스트를 매번 다시 넣는 일이 사용량을 더 크게 키울 수 있습니다.

동일 세션·캐시·결정론적 검증을 먼저 유지하세요.

지수 계산 방식

모델별 입력·출력 단가 비율은 모두 동일하게 1:6이므로, 같은 입·출력 비율의 작업에서는 표준 단가 비율이 그대로 비용 지수가 됩니다. 가성비는 Terminal-Bench 성공률을 xhigh 예상 사용량으로 나눈 뒤, 각 벤치 버전의 기준 모델을 100으로 맞췄습니다.

사용량 지수 = 모델 단가 비율 × effort 계수
