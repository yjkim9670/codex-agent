# Claude 실행 지연 조사 및 진단 로깅 제거 기록

2026-10-22, 추가 성능 개선을 중단하고 상시 진단 수집을 제거했다. 이 문서는
당시 구현·관측·한계를 나중에 검토하기 위한 기록이다.

## 현재 동작

- 사내/사외 모두 새 `company_timing` 보고서를 만들거나 메시지에 저장하지 않는다.
- `CODEX_TIMING_ENABLED`, `CODEX_CLAUDE_STARTUP_DIAGNOSTICS`는 더 이상 읽지 않는다.
  기존 환경에 값이 남아 있어도 수집이 켜지지 않는다. `CODEX_COMPANY_MODE`의
  인증·모델·사내 기능 동작은 유지한다.
- Claude 명령에 진단용 `--debug-file`을 추가하지 않고, 진단 폴더 생성·첫 바이트
  측정·종료 후 디버그 파일 스캔도 수행하지 않는다.
- 출력 줄별 바이트 수, Claude 이벤트별 개수·간격·모델/usage 중복 집계,
  저장 함수·잠금별 시간 측정, 보고서 복사·직렬화·INFO 출력을 제거했다.
- `Agent lifecycle` INFO 로그와 최근 64개 `diagnostic_timeline` 수집/응답을 제거했다.
  작업 상태에 필요한 현재 `diagnostic_phase` 하나만 메모리에 유지한다.
- 타임 보고서만을 위한 완료 후 세션 재저장을 제거했다. 정상 응답·부분 응답 저장,
  실제 사용량 집계·후처리, 시간 제한·취소·저장 실패 처리는 유지한다.
- `Session store saved ... elapsed_ms=...` INFO 계측도 제거했다. 원자적 저장과
  기존 오류 로그는 유지한다.
- 초기화 비교 전용 `scripts/compare_claude_startup.py`와
  `services/claude_diagnostics.py`, 해당 전용 테스트는 삭제했다.

기존 메시지의 타임 로그 메타데이터와 이를 열람하는 화면은 보존한다. 새 응답에는
해당 메타데이터가 없어 타임 로그가 추가되지 않는다. 과거 원본 로그·세션 파일은
일괄 삭제하거나 재저장하지 않았다. 원본은 민감한 내용을 포함할 수 있으므로 이
문서에는 복사하지 않는다. 명시적으로 실행하는 backend/model 검증 도구의 결과
파일 수집은 서버의 상시 수집과 별개이며 유지한다.

실행 중인 서버는 변경하지 않았다. 사용자가 서버를 재시작한 뒤 새 요청부터 적용된다.

## 나중에 조사를 재개한다면

이전 계측은 `schema_version: 2`, 고정 `spans`, 최근 64개 `timeline`, 저장 작업
`operations`, `request`, `cli`를 포함했다. 구간은 monotonic 시계 기준이며,
`operations`의 잠금·읽기·쓰기·트랜잭션은 서로 포함 관계이고 구간과도 겹친다.
**구간과 저장 집계를 합산하지 않는다.** 관측 경계가 없는 구간은 0ms가 아니다.
브라우저 전송, CLI 내부 DNS/TLS·인증·서버 큐·추론을 개별 측정한 자료도 아니다.

재검토 후보 순서는 최소 셸 명령과 스냅샷 생성, 텔레메트리 설정에 따른 종료 시간,
제목 생성과 초기 로그 공백이다. 변경은 이번에 시행하지 않았다. 같은 장비·인증·
endpoint·모델·effort·프롬프트로 조건당 한 항목씩 바꾸고 여러 회차를 비교해야 한다.
과거 비교 도구는 디버그 없음/있음, MCP 제한, user 설정만, 명령 비활성화,
빈 작업 폴더를 비교하고 워밍업을 분리했으나 현재 실행 도구는 삭제했다.

상세 로깅 자체도 디버그 파일 쓰기, 줄별 잠금·인코딩, 이벤트별 집계,
종료 후 최대 4 MiB 스캔, 보고서 복사·직렬화와 전체 세션 재저장 비용이 있었다.
그 비용이 몇 ms 또는 몇 %였는지는 측정하지 않았다. macOS 모의 테스트는
사내 Windows 실제 지연을 입증하지 않는다. 재도입한다면 제한된 수동 진단으로
분리하고, 원본 로그의 보관 기간·크기와 계측 없음 대비 비용을 함께 검토한다.

## 정리 후 검증

Python 3.14에서 실행 제한, 세 backend 정상 완료·취소, 저장 실패, 예전 환경변수
잔존 시 Claude 디버그 미생성, stderr 처리, OpenCode 취소 경합을 포함해
관련 테스트 24개가 통과했다. backend/model 검증 도구 테스트 28개와
`node tests/test_company_timing.cjs`의 과거 보고서 렌더링 검사도 통과했다.
`git diff --check`에서 오류가 없었다.

전체 스트림 테스트 파일의 실행은 별도 기존 실패로 중단되었다. 사용량 이력
테스트 3개와 동기 CLI 호출 테스트 3개(Python 버전 검사 모의 응답 문제)를
수정 전 HEAD 코드를 메모리에 로드해서도 각각 재현했다. 해당 문제는 이번
로깅 제거에서 수정하지 않았으며 전체 테스트 통과를 주장하지 않는다.
