# Chat 사용량 보정 연결과 과거 복구 검증

2026-11-03, canonical checkout에서 구현·검증했다. 운영 서버와 원본 사용량 원장은 변경하거나 재시작하지 않았다.

## 과거 Luna 6 XHigh 19건

보존된 수집 캐시, 보정 원장, 한도 조회 이력으로 별도 후보 원장을 생성했다. 원본을 덮어쓰는 옵션은 제공하지 않는다.

| 한도 | 다른 실행과 시간 중복 | 실행 전 기준 한도 검증 부족 | 안전한 복구 후보 |
| --- | ---: | ---: | ---: |
| 5시간 | 8 | 11 | 0 |
| 주간 | 13 | 6 | 0 |

19건 각각의 두 한도에 대한 결과다. 두 행을 합쳐 실행 건수로 읽으면 안 된다. 기준 한도 검증 부족은 실행 전 15분 이내의 가장 최근 보존 표본으로 당시 기준 사용률과 리셋을 함께 확인하지 못했다는 뜻이며, 조회 자체가 전혀 없었다는 뜻은 아니다. 중복 검사는 기준 한도를 관측한 시점부터 사용률 증가를 관측한 시점까지의 다른 실행을 포함한다. 원장이 가진 기준값만 믿거나 중복 조건을 완화해 단독 모델 차감률을 만들지 않는다.

검증 명령:

```sh
python3.14 scripts/verify_usage_recovery.py \
  --account-root /Users/dinya/.codex-workbench/accounts/yangjina-kim \
  --output-dir .agent_state/usage-recovery-2026-11-03
```

출력 `recovery-audit.json`은 입력 SHA-256, 실행 중 원본 불변 여부, 건별 판정, 후보 분석 결과를 담는다. `candidate-calibration.json`은 별도 후보 원장이다. 이번에는 복구 후보가 0건이므로 기한 초과 제외를 변경하지 않았다.

## 새 Chat 관측

- 실행 직전에 동일 RPC로 캐시 없는 기준 한도를 조회한다. 완료 직후와 30초 후에도 조회하며, 조회 실패는 대화 실패로 전파하지 않는다.
- 관측은 Chat SQLite의 전용 테이블과 내구성 있는 outbox에 저장한다. 완료 후 조회가 실행 완료 시각을 옮기지 않으며, 대화 삭제 이후 도착한 관측도 outbox에 반영한다.
- 공통 수집기가 계정 경계를 확인하고 rollout으로 토큰을 대조한다. rollout으로 이벤트 ID가 바뀌어도 Chat 보정 ID를 유지하며, 모델별로 여러 이벤트가 나오면 불명확한 대응을 강제로 연결하지 않는다.
- 수집기는 기존 계정 보정 원장에 잠금·원자적 쓰기로 반영한다. 원본 작업 원장과 한도 조회 이력은 재작성하지 않는다. Chat의 정확한 관측 표본은 해당 보정 기록에 함께 저장하므로 기존 시간 버킷으로 합쳐져 없어지지 않는다.
- 한도별로 기준 한도, 리셋, 양수 차감, 실행 중복을 검증한다. Chat 보정 대기 기록은 작업 모드의 묶음 차감 처리에서 제외하고 공통 수집기가 후속 관측으로 다시 검증한다. 24시간이 지나도 관측되지 않으면 기한 초과로 표시한다.
- 기존 Chat 기록은 실행 전 한도가 없으므로 소급해서 정상 보정 기록을 만들지 않는다. 수집 토큰은 유지하고 보정 기록 없는 토큰으로 구분한다.

관측을 추가해도 다른 모델과 동시에 사용한 구간이나 관측 부족 구간은 단독 차감률로 인정하지 않는다. 다른 PC나 클라우드의 미추적 사용은 로컬 로그만으로 배제할 수 없다. 정수 사용률, 조회 지연 및 0 변화 구간 제외도 추정에 영향을 준다.

## 화면과 검증

모델/effort별로 전체 수집 토큰, 보정 기록 없는 토큰, 검증 통과 토큰을 분리한다. 제외 숫자에는 보정 기록의 `건`과 관측 묶음의 `구간`을 붙인다. 3개 미만 검증 구간의 차감률은 계속 숨긴다.

관련 Python 테스트 69개 통과, 네이티브 CLI 감사 테스트 1개는 기존 opt-in 조건으로 생략했다. 대시보드 렌더링 테스트와 지정 `verify_browser_ui.py` runner도 통과했다. 브라우저 검증에는 임시 loopback fixture 서버를 사용하고 종료했다. 실제 계정 모델 요청은 실행하지 않았다. 프로젝트 지침에서 참조한 `design.md`는 checkout에 없어 기존 화면 구조와 스타일을 유지했다.

적용하려면 사용자가 Workbench 서버와 `Workbench Chat - conversation server`를 재시작해야 한다. 재시작 이후 새 Chat 실행부터 기준 한도가 수집되며, 공통 수집 주기는 최대 약 5분이다. Git 동기화는 사용자 관리 범위다.

## 동일 조건 연속 Chat 관측 개선 (2026-11-03)

Chat 보정 계산을 `chat_homogeneous_observation_v2`로 변경했다. 각 한도에서 실행 시작 순으로 검증하며, 최초 기준 한도부터 양수 차감 관측까지 포함된 완료 Chat 실행을 동일 계정·provider 계정·모델·effort의 순차 실행일 때 하나의 묶음으로 인정한다. 개별 실행의 토큰은 유지하고, 묶음 전체 차감량은 분석에서 한 번만 합산한다. 5시간과 주간은 서로 다른 묶음이 될 수 있다.

작업 모드 사용, 다른 모델/effort, 동시 실행, 진행 중이거나 토큰 확정 전인 실행, 검증되지 않은 기준 한도, 리셋 변경은 계속 제외한다. 이미 집계한 관측 이전의 오래된 기준값으로 다음 차감을 다시 집계하지 않는다. 기존 관측이 있는 Chat 기록은 공통 수집 시 재계산되지만, 실행 전 관측이 없는 과거 사용은 계속 연결하지 않는다. 수집 캐시가 유효하면 다음 수집까지 최대 약 5분이 걸린다.

Chat 사용량 화면은 ISO 날짜 문자열과 기존 epoch 초 형식을 모두 처리하여 브라우저 현지 시간으로 리셋 시각을 표시한다. 조회 결과에 날짜가 없거나 잘못된 경우만 `시간 미제공`을 표시한다. 브라우저 fixture의 5시간 한도도 실제 provider와 동일한 ISO 형식으로 변경했다.

적용하려면 Workbench 서버의 재시작이 필요하다. Chat 화면은 새로고침하여 최신 JavaScript를 불러온다. 운영 서버와 원본 계정 원장은 이번 수정 과정에서 변경하지 않았다.
