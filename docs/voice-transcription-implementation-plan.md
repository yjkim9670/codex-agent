# 음성 전사 시험과 Codex Workbench 구현 계획

작성일: 2026-11-06. 상태: 구현 및 검증 진행 중.

## 시험 결과

- 입력: Galaxy Fold8에서 녹음한 첨부 M4A, AAC 모노 48 kHz, 301.76초, 4,889,227바이트. 기기명은 사용자 제공 정보다.
- 환경: Apple M5, 메모리 24 GiB, macOS, ffmpeg 9.0.2, whisper.cpp 1.9.5. 기존 `ggml-large-v3-turbo-q5_0.bin` 다국어 모델(약 547 MiB)을 외부 프로젝트에서 읽기만 했다. 제품 배포 시 해당 경로가 존재한다고 가정하면 안 된다.
- `ffmpeg`로 16 kHz 모노 PCM WAV로 변환하고 `whisper-cli -l ko`로 전사했다. 전사 명령의 실제 경과 시간은 22.64초, whisper 내부 총 시간은 17.54초다. 파일 변환과 업로드 시간은 제외하며 단일 실행이므로 보장 성능이 아니다.
- 시험 원본과 전사 결과는 사용자 요청으로 삭제했다. 원본과 결과를 외부 서비스로 전송하지 않았다.
- 한국어 문장과 대화의 흐름이 출력되어 로컬 전사 가능성은 확인했다. 다만 반복되는 추임새와 문맥상 어색한 단어가 있으며, 원음을 직접 청취해 대조하지 못했다. 따라서 정확도, 누락, 화자 분리 및 의학 용어의 신뢰도는 확인되지 않았다. 결과를 사실로 확정하거나 자동 전송하지 않는다.
- 다음 품질 검증: 사용자가 원음과 전사문의 시작·중간·끝 및 고유명사/숫자 구간을 대조하고, 별도 30~60초 프롬프트 녹음의 정답 전사와 비교한다. 조용한 환경, 주변 소음, 한국어·영어 혼용을 포함하고 명령 수행에 영향을 주는 오류를 기록한다. 필요하면 정답 전사 기준 CER/WER을 계산한다. 이번 1회 대화 시험만으로 목표 정확도를 주장하지 않는다.

재현 명령(작업 디렉터리: 저장소 루트, 모델 경로는 환경에 맞게 지정):

```sh
ffmpeg -nostdin -v error -y -i INPUT.m4a -ar 16000 -ac 1 -c:a pcm_s16le /tmp/workbench-voice-test.wav
whisper-cli -m MODEL.bin -l ko -f /tmp/workbench-voice-test.wav -otxt -osrt -of OUTPUT_PREFIX
```

임시 WAV에는 원음이 들어 있으므로 재현 후 직접 삭제한다. 실제 시험의 WAV와 로그는 정리했다.

## 적용 범위와 현재 구조

1차 목표는 **채팅 프롬프트 입력을 위한 녹음 후 전사**다. 기존 텍스트를 보존하고 사용자가 전사 결과를 확인·수정한 다음 직접 전송한다. 실시간 자막, 화자 구분, 요약, 음성 파일 자동 전사는 1차 범위에서 제외한다.

- 입력 UI는 `codex-web-app/templates/index.html`의 `#codex-chat-input`, 관련 동작은 `codex-web-app/static/js/app.js`다. 기존 파일 첨부는 `/api/codex/attachments`와 `services/codex_chat.py`를 사용하며 기본 파일당 20 MiB 제한이 있다. 첨부 처리와 전사는 별도 기능으로 둔다.
- `CODEX_MAX_PROMPT_CHARS`는 현재 4,000자다. 전사 결과가 이를 넘으면 잘라서 조용히 잃지 말고, 결과 전체를 표시하면서 삽입 가능 분량을 명시하고 사용자가 선택·편집하게 한다. 서버의 실제 검증과 UI 글자 수 계산의 단위를 구현 시 일치시킨다.
- Android 앱의 현재 매니페스트에는 `RECORD_AUDIO`가 없고, 확인한 WebView 코드에는 `onPermissionRequest` 처리가 없다. 브라우저에서의 성공이 앱 WebView 성공을 뜻하지 않는다.

## 권장 설계

### 1. 녹음과 편집

- 입력창 가까이에 접근 가능한 마이크 버튼과 녹음 시간, 중지/취소, 처리 상태를 둔다. 상태는 대기 → 권한 요청 → 녹음 → 업로드/전사 → 결과 확인 → 삽입이며 오류와 취소는 안전하게 대기로 돌아간다. 모든 종료 경로에서 마이크 트랙을 중지한다.
- `getUserMedia`와 `MediaRecorder`를 사용하고, 지원 MIME을 `MediaRecorder.isTypeSupported`로 선택한다. WebM/Opus와 MP4/AAC는 서버의 실제 ffmpeg 디코딩을 검증한다. 지원되지 않거나 HTTPS/권한이 없는 경우 원인과 해결 방법을 보여준다. 보안 컨텍스트와 권한이 필요하다: [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static).
- 초기 제한 제안: 녹음 5분, 업로드 20 MiB. 제한 도달 전 안내 후 안전하게 중지하고 녹음된 내용을 처리한다. 네트워크 단절/실패 시 메모리의 녹음이 남아 있는 동안 재시도 또는 다운로드할 수 있게 한다. 탭 종료나 OS 백그라운드 중단 시 보존은 보장하지 않으며 명시한다.
- 전사 완료 시 별도 편집 영역에서 원문을 보여주고 '입력창에 삽입'을 누르게 한다. 시작 시 선택 위치와 기존 초안을 보존하고, 전사 중 초안/세션이 바뀌면 현재 활성 입력에 덮어쓰지 않고 확인하게 한다. 자동 제출하지 않는다.

### 2. 서버 전사

- 신규 전용 multipart API와 서비스 모듈을 만든다. 현재 인증·접근 제어, CSRF/origin 정책, 경로 접두어 및 프록시 크기 제한을 조사해 같은 보호를 적용한다. 임의의 서버 경로 또는 모델 경로를 요청자가 전달하지 못하게 한다.
- 스트리밍 크기 제한과 오디오 디코딩/길이 확인을 적용한다. MIME·확장자는 참고만 하고 ffprobe/ffmpeg로 검증한다. 입력 크기 외에 디코딩 후 길이도 제한하고 실행 시간, CPU/메모리, 임시 디스크 사용량을 제한한다. ffmpeg와 whisper는 인자 배열로 실행하고 shell을 사용하지 않는다.
- 짧은 동기 HTTP 요청에 5분 녹음을 묶지 않는다. 생성 `POST` → 상태 조회 `GET` → 취소 `DELETE`의 작업 API를 사용한다. 작업은 요청 사용자/세션에 귀속하고 임의 ID 접근을 막는다. 대기열과 동시 실행 수를 제한하며, 중복 제출을 방지한다. 완료 결과는 제한된 시간만 보관하고 취소·오류·만료·서버 재시작 시 임시 파일을 정리한다. 취소 시 자식 프로세스까지 종료하고 경합을 검사한다.
- ffmpeg로 16 kHz 모노 PCM 변환 후 whisper.cpp 다국어 모델과 `ko`를 사용한다. 명령 위치, 모델 위치, 활성화 여부, 제한값을 서버 관리자가 설정한다. 모델 파일의 출처·무결성 및 라이선스를 확인하고 독립적으로 준비한다. 시작/상태 점검에서 도구 또는 모델 누락을 명확히 알리고 기존 채팅은 정상 동작시킨다. 음성 및 전사 텍스트는 로그에 남기지 않는다.
- 원본과 변환 파일은 접근 제한된 작업별 임시 디렉터리에 저장하고 종료 시 삭제한다. 전사 결과도 최소 보관하며 삭제 정책과 백업/로그 범위를 문서화한다. 외부 전사 API는 사용하지 않는다.

### 3. Android WebView

- `MainActivity` 등 실제 진입 WebView에 `RECORD_AUDIO` 선언과 Android 런타임 권한 요청을 추가한다. `WebChromeClient.onPermissionRequest`에서 현재 신뢰된 HTTPS origin의 오디오 캡처만 허용하고, 다른 origin·자원은 거부한다. 권한 거부, 요청 취소, 화면 이동/종료 및 재요청을 처리한다. 동적으로 서버 주소를 바꾸는 기존 앱의 origin 검증을 재사용하거나 명시적으로 설계한다. [Android WebChromeClient](https://developer.android.com/reference/android/webkit/WebChromeClient#onPermissionRequest(android.webkit.PermissionRequest)).
- 실제 Galaxy 기기의 Chrome과 Workbench 앱에서 각각 권한, 녹음 형식, 전송, 백그라운드 중단, 재진입을 확인한다. HTTPS 경유 설정과 프록시 타임아웃도 점검한다.

## 구현 순서와 완료 기준

1. **품질 확인**: 위 원음 대조 및 짧은 프롬프트 시험을 먼저 수행해 오류 사례를 확보한다. 필요 시 모델/설정 비교 후 선택한다.
2. **서버**: 설정, 제한된 작업 큐, 변환·전사·취소·정리 및 상태 API 구현. 유효/손상/무음/초과 길이, 도구 부재, 타임아웃, 동시 요청, 사용자 간 격리, 중복 취소와 파일 정리를 테스트한다.
3. **웹**: 녹음·상태·결과 편집·삽입 구현. 초안 보존, 4,000자 제한, 권한 거부, 지원 형식 부재, 재시도와 세션 변경을 테스트한다. 일회성 로컬 서버에서 프로젝트 지정 브라우저 검증을 실행한다.
4. **Android**: 최소 권한과 origin 검증을 구현하고 실기기에서 Chrome과 WebView를 따로 검증한다.
5. **인수**: 실제 한국어 명령을 말해 결과 확인 → 수정 → 기존 초안에 삽입 → 사용자가 직접 전송하는 전 과정을 통과한다. 서버 재시작/배포는 사용자가 수행한다. 성능은 업로드부터 결과 표시까지 기기별로 여러 번 측정해 보고하며, 품질 및 목표 지연은 사용자와 시험 결과로 확정한다.

## 사용 설정과 현재 구현 상태

서버 환경에서 `CODEX_VOICE_ENABLED=true`와 `CODEX_VOICE_MODEL=/절대/경로/모델.bin`을 지정하거나, Git에서 제외되는 `.local/voice/config.json`에 같은 키와 문자열 값을 저장한다. 환경변수가 JSON보다 우선하며 기본값은 비활성화다. 런처는 `.env`를 자동으로 읽지 않는다. `ffmpeg`, `ffprobe`, `whisper-cli`는 서버 프로세스의 PATH에서 찾으며 필요하면 `CODEX_VOICE_FFMPEG`, `CODEX_VOICE_FFPROBE`, `CODEX_VOICE_WHISPER_CLI`에 실행 파일의 절대 경로를 지정한다. JSON의 상대 모델 경로는 `.local/voice/` 기준이다. 모델은 별도로 준비하고 출처·무결성·라이선스를 관리자가 확인한다. 모델을 Git에 포함하거나 다른 프로젝트 경로를 기본값으로 지정하지 않는다. 코드 적용 시 사용자가 서버를 재시작해야 한다. 이후 JSON 수정은 새 작업부터 적용되며 실행 중인 작업은 검증된 설정을 유지한다. 예시는 README의 Local voice transcription을 참고한다.

MediaRecorder WebM은 길이 메타데이터가 없을 수 있으므로 최대 302초만 WAV로 디코딩한 후 실제 PCM 길이를 확인한다. 300초 제한에 컨테이너 오차 1초를 허용하며, 초과분을 조용히 잘라서 성공 처리하지 않는다. 디코딩 입력의 네트워크 프로토콜은 허용하지 않는다. 상태 및 결과 API에는 `Cache-Control: no-store`를 적용한다.

음성은 로컬 처리하며 작업별 접근 제한 임시 디렉터리에 저장하고 작업 완료·실패·취소 후 삭제한다. 프로세스가 비정상 종료된 경우 다음 음성 API 사용 시 종료된 프로세스의 임시 디렉터리를 정리한다. 전사 결과는 프로세스 메모리에 최대 10분 보관하고 취소 또는 삽입 시 삭제를 요청한다. 음성 내용과 전사문을 애플리케이션 로그에 기록하지 않는다. 브라우저 탭 종료나 모바일 백그라운드 중단 시 녹음 보존은 보장하지 않는다.

동시 처리는 서버 프로세스당 한 건이며 추가 요청은 대기하지 않고 재시도를 안내한다. 20 MiB와 5분 제한을 적용한다. 다중 서버 프로세스 사이에 큐나 작업 상태를 공유하지 않으므로 현재 단일 프로세스 구성에서 사용해야 한다. 실행 시간과 디코딩 길이를 제한하지만 OS 수준 CPU·메모리 상한은 아직 설정하지 않았다. 프록시 업로드 크기 제한도 별도로 확인해야 한다. Galaxy 실기기 Chrome 및 Android WebView 검증, 백그라운드 중단 시험, 실제 발화 인수 시험은 남아 있다.
